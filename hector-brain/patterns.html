Patterns

How common interactions work in Hector Brain. Everything here is live: click to try it. Rules in docs/INTERACTIONS.md.

Menus (⋯)

Use for: actions on one thing (a chat, a workspace). Opens next to the button; Esc or a click outside closes it. Destructive items go last, in red, after a divider.

Rename in place

No pop-up. The name turns into a text field with the text selected. Enter or clicking away saves, Esc cancels. A toast confirms with Undo.

Confirm before deleting

Only for things that can’t be undone. Name the item in the title, say what happens to related things, and put the red action on the right. Cancel is always there; Esc cancels.

Create something

A short dialog with only what’s needed to create it (1–2 fields). The main button stays disabled until the required field is filled; Enter submits. Anything longer gets its own page.

Share

One dialog: the link, Copy link (the button says “Copied” for a moment), and an on/off switch for link sharing.

Toasts

For confirming something that just happened. Bottom centre, dark, one short line. Reversible actions (pin, rename, move, archive) get Undo and stay 5 seconds; others leave after 2.

Tooltips

Every icon-only button has one: dark, one to three words, shown after a short pause on hover or keyboard focus. Never put essential information only in a tooltip.

Problems that need the user

Only show colour when something is wrong. Amber = needs attention, red = something failed. Say what happened, what it means, and give one button to fix it.
